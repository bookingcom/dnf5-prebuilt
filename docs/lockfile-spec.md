# Lockfile Specification (`rpm_lock`)

This document defines the JSON lockfile format generated by the `dnf5 lock`
command plugin (`bazel/dnf5/plugins/lock*`) via the `rpm_lock` Bazel rule and
consumed by the `dnf5.lock` Bzlmod module extension.

---

## 1. Overview

An `rpm_lock` lockfile is a deterministic, UTF-8 encoded JSON document (`.lock.json`)
that captures the complete resolved RPM package closure for a set of requested
package specifications, ordered topologically so that dependencies are extracted
before their dependents.

### Design Principles

1. **Compact & Non-Redundant**: Only fields required to fetch, verify, and order
   packages are emitted by default. Fields derivable from existing fields (such
   as `nevra` or hexadecimal `checksum`) are omitted.
2. **Topological Installation Order**: Both `install_order` and `packages` are
   emitted in topological installation order (computed via Kahn's algorithm over
   resolved `Requires` providers, with `filesystem` ordered first when present
   so root directory symlinks such as `/lib64 -> usr/lib64` exist before any
   package unpacks files into them).
3. **Deterministic Formatting**: All sets are lexicographically sorted, cycle
   tie-breaking is deterministic (fewest remaining dependencies, then
   lexicographical package name), and JSON output is pretty-printed via
   `json-c` (`JSON_C_TO_STRING_PRETTY`).
4. **Opt-In Debugging Metadata**: Dependency graph inspection fields
   (`dependencies`, `transitive_dependencies`, `recommends`, `supplements`) are
   omitted by default and included only when `--debug` (`debug = True` on
   `rpm_lock`) is enabled.

## 2. Top-Level Object Schema

| Field | Type | Presence | Description |
|---|---|---|---|
| `version` | `integer` | Always | Schema version. Always `1`. |
| `arch` | `string` | When `archlist` is non-empty | Comma-separated target architectures passed via `--archlist` (e.g. `"x86_64,noarch"`). |
| `requested` | `array of string` | Always | Sorted list of directly requested package names and specs. |
| `install_order` | `array of string` | Always | Package names ordered in topological installation sequence. Matches `[pkg.name for pkg in packages]`. |
| `obsoleted` | `array of object` | Only when non-empty | Packages from `base_rpmdb` replaced (`REPLACED`) by a package of a different name during resolution. Each entry contains `name`, `version`, and `arch`. |
| `packages` | `array of object` | Always | Resolved package entries ordered in topological installation sequence (`install_order`). |

---

## 3. Package Object Schema (`packages[]`)

### Standard Fields (Always Emitted)

| Field | Type | Presence | Description |
|---|---|---|---|
| `name` | `string` | Always | RPM package name (`%{name}`, e.g. `"curl"`). |
| `version` | `string` | Always | Epoch-Version-Release (`[epoch:]version-release`, `%{evr}`, e.g. `"8.12.1-4.el10_2.7"` or `"1:3.5.8-2.0.1.el10_2"`). |
| `arch` | `string` | Always | Package architecture (`%{arch}`, e.g. `"x86_64"`, `"aarch64"`, `"noarch"`). |
| `url` | `string` | Always | Resolved download URL (`https://...`, `http://...`, or `file://...`). Forward slashes are escaped (`\/`) by `json-c`. |
| `integrity` | `string` | Always | Subresource Integrity (SRI) digest in `<algorithm>-<base64>` format (e.g. `"sha256-u1dQyIIF/W722XdebDs0fVyPZErKJ8+kaN/ZEwFox58="`). |
| `requested` | `boolean` | Only when `true` | Set to `true` if the package was directly requested by the caller; omitted for transitive dependencies. |

> **Deriving NEVRA**: When a canonical NEVRA string is needed, derive it as
> `"{name}-{version}.{arch}"`.

### Debug Fields (`--debug` / `debug = True` Only)

When `dnf5 lock --debug` (or `rpm_lock(..., debug = True)`) is enabled, each
package entry additionally includes:

| Field | Type | Presence (`--debug`) | Description |
|---|---|---|---|
| `dependencies` | `array of string` | Always in `--debug` | Sorted list of direct runtime dependency package names (within the resolved closure or `base_rpmdb`). |
| `recommends` | `array of string` | When non-empty in `--debug` | Weak `Recommends` dependency expressions from package metadata. |
| `supplements` | `array of string` | When non-empty in `--debug` | Reverse weak `Supplements` dependency expressions from package metadata. |
| `transitive_dependencies` | `array of string` | Always in `--debug` | Sorted list of all transitive runtime dependency package names. |

## 5. Consumption by Bzlmod (`dnf5.lock`)

The `dnf5.lock(name, lockfile)` tag in `@dnf5-prebuilt//dnf5-prebuilt:extensions.bzl`
reads a `.lock.json` file at module evaluation time:

1. Creates an `@bazel_tools//tools/build_defs/repo:http.bzl` `http_file`
   repository `@<name>__<pkg>` for each entry in `packages`, using `url` and
   `integrity`.
2. Orders the package list according to `install_order` (falling back to the
   order of `packages`).
3. Generates a hub repository `@<name>` containing:
   - `@<name>//:rpms`: a `filegroup` listing all `@<name>__<pkg>//file` targets
     in topological `install_order`, ready to pass directly to `rpm_layer` and
     `rpm_mark`.
   - `@<name>//:<pkg>`: an `alias` for each individual package.
   - `@<name>//:defs.bzl`: exports `RPMS` (the ordered list of `@<name>__<pkg>//file`
     label strings).
